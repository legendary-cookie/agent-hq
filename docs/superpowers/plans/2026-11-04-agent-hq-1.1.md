# Agent HQ 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** opencode Ask me over ACP, Antigravity live follow-ups, office extras, Orchestrate (goals of planned steps), remote runs on Linux/macOS hosts, then publish the repository.

**Architecture:**
- **Live tools.** They get an optional per-run *protocol driver*: a stateful object that turns agent output lines into events and replies. opencode's ACP driver uses it.
- **Goals.** A scheduler sits above the existing Runner. Each step is a normal run whose worktree starts from the goal branch.
- **Remote runs.** These reuse the launchers. A fixed helper on the host is reached over the same ssh path as watching.
- **Office extras.** These are web-only, plus one read-only timeline endpoint.

**Tech Stack:** Python 3.11+ stdlib; React 18.3.1 + TS + Vite 5.4.11 + PixiJS 8.6.6 (existing).

**Spec:** [docs/superpowers/specs/2026-11-04-agent-hq-1.1-design.md](../specs/2026-11-04-agent-hq-1.1-design.md)

## Global Constraints
- All M5a, Steer and remote-watching constraints still apply: stdlib only; no shell; no `npm install`; tests never run real agent tools or ssh; validated session ids; never-auto rules; read-only rule allowlist.
- **opencode ACP**, from a real probe on 2026-11-04. Keep these exact.
  - **Launch:** `opencode acp --cwd <workdir>`, through the npm-shim resolver, with env `OPENCODE_CONFIG_CONTENT={"model":<model or null>,"permission":{"edit":<p>,"bash":<p>}}`. `<p>` is `"ask"` for level ask and `"allow"` for edit. Read-only isn't offered for opencode.
  - **Handshake:**
    1. `initialize` `{"protocolVersion":1,"clientCapabilities":{"fs":{"readTextFile":false,"writeTextFile":false},"terminal":false}}`;
    2. `session/new` `{"cwd":<workdir>,"mcpServers":[]}`, which returns `result.sessionId`. To resume, use `session/load` `{"sessionId","cwd","mcpServers":[]}`;
    3. `session/prompt` `{"sessionId","prompt":[{"type":"text","text":…}]}`, which returns `{"stopReason"}` at the end of a turn.
  - **Permission:** request `{"method":"session/request_permission","id":N,"params":{"toolCall":{"title","kind","rawInput",…},"options":[{"optionId","kind":"allow_once|allow_always|reject_once|reject_always"}]}}`. Reply `{"id":N,"result":{"outcome":{"outcome":"selected","optionId":<id of the matching kind>}}}`. Allow maps to the `allow_once` option and deny to `reject_once`; never use the `*_always` options. If no option of that kind exists, reply `{"outcome":"cancelled"}`.
  - Any other agent→client request gets the JSON-RPC error `{"code":-32601,"message":"not supported"}`.
- **Antigravity live:** stdin `{"event":"user","message":{"role":"user","content":<text>}}`, flags `--input-format stream-json --output-format stream-json` with **no** `-p=<prompt>` (an empty `-p=` is allowed). Ask me stays off.
- **Goals:**
  - max steps: default 6, at most 10;
  - step prompt: at most 20,000 characters;
  - total time: default 90 min, at most 240;
  - step level: `min(goal max level, kind default)`, where review and research default to read_only and code to edit;
  - **full_auto is never allowed** for steps, and the goal's max level must be one of `read_only`, `ask`, `edit`.
- **Remote runs:** Linux and macOS only, with `"run": true` and `"projects"` in `hosts.json`. The helper is stdlib-only, Python 3.8 syntax, and sent over the same ssh argv as watching, plus `-o ServerAliveInterval=15`.
- **Timeline:** `GET /api/timeline?from=&to=` returns at most 20,000 events, with only `session_id, ts, kind, tool, harness` and no previews.

## Review Focus
1. **A planner that returns hostile JSON:** levels above the max, `full_auto`, unknown tools, dependency cycles, 11 steps, a 1 MB prompt, or non-JSON prose. Every one must be refused or capped, and nothing runs before Start. Pinned in Task 4: `test_hostile_plans`.
2. **A step merge conflict on the goal branch.** The goal must pause, your checkout must stay untouched, and the other branches must stay intact. Pinned in Task 5: `test_step_conflict_pauses_goal`.
3. **ACP replies that answer the wrong request**, or reuse an `allow_always` option. Only `allow_once` / `reject_once` are ever sent, matched by request id. Pinned in Task 1: `test_acp_never_sends_always_options`.
4. **A remote helper request with a forged project name or argv**, for example a project outside the host allowlist, or argv starting with `sh`. The helper must refuse on the remote side even if the local checks were skipped. Pinned in Task 7: `test_helper_refuses_unlisted_project_and_tool`.
5. **A dropped ssh connection during a remote run.** The run must become `interrupted`, and the remote process group must be killed by the helper's watchdog. Pinned in Task 7: `test_helper_kills_group_when_stdin_closes`.

### Task 1: Protocol drivers, opencode ACP and Antigravity live
**Files:**
- Create: `hq/run/drivers.py`, `hq/run/acp.py`
- Modify: `hq/run/launchers/base.py`, `opencode.py`, `agy.py`; `hq/run/runner.py` (use a driver when the launcher has one)
- Test: `tests/test_run_acp.py`

**Interfaces:**
- `Driver` protocol: `start(prompt) -> list[str]` (lines to write), `on_line(line) -> tuple[list[StreamEvent], list[str]]` (events, reply lines), `follow_up(text) -> list[str]`, `answer(request_id, decision, note) -> list[str]`, `session_id -> str | None`.
- `BaseLauncher.make_driver(req, resume_session_id=None) -> Driver | None`: None by default, which keeps today's line handling.
- `AcpDriver`:
  - does the handshake; the prompt and follow-ups are sent after `session/new` (or `session/load`) returns;
  - the session id is validated with `valid_session_id`;
  - `session/update` notifications become `working` events with text;
  - a `session/prompt` result becomes `turn_end`;
  - `session/request_permission` becomes a `permission` event, with `request = {request_id, tool_name: toolCall.kind or 'edit', input: toolCall.rawInput or {'file_path': toolCall.title}}`.
- opencode: `steer_mode = 'live'`, `can_ask = True`, levels `{'ask', 'edit'}`; `build` gives the ACP argv and env.
- Antigravity: `steer_mode = 'live'`, `user_message` / `first_input` in the `event` shape, and `build` without a prompt in argv.
- The Runner uses `driver.start(...)` for the first input, `driver.on_line` for every stdout line, `driver.follow_up` in `send`, and `driver.answer` in the approval reply.

**Interfaces:**

  - routing uses the step's tool, or the guard's auto pick;
  - the total time limit stops all of the goal's runs.
- **Goal statuses:** `planning`, `review`, `running`, `needs_you`, `done`, `failed`, `stopped`.

### Task 7: Remote runs
**Files:**
- Create `hq/remote/runner_helper.py` (standalone, Python 3.8) and `hq/remote/remote_runs.py`.
- Modify `hq/remote/config.py` (`run`, `projects`), the launchers (a `host` option for argv building) and `hq/run/runner.py`/`service.py` (a host on requests).
- Test: `tests/test_remote_runs.py`.

**Interfaces:**
- **Helper actions:** `tools`, `start`, `stop`, `diff`, `merge`, `discard`, chosen by an embedded request literal (as with the scanner).
- **On `start`, the helper:**
  - checks the project against its copy of the host's project list (sent in the request, re-validated: absolute path, a git repo, no `..`);
  - checks `argv[0]` against the tool list (`claude`, `codex`, `opencode`, `agy`), resolved with `shutil.which`;
  - creates the worktree with explicit git dirs;
  - runs `os.setsid` + `os.execvp`, through a fork that streams stdout;
  - writes `~/.agent-hq/runs/<id>.pid`;
  - acts as a watchdog: when its stdin hits EOF, it sends the group SIGTERM, then SIGKILL.
- `RemoteRuns(host, run_scan-like transport)` streams lines into the runner as a child-like object with `kill_tree` (a second ssh `stop` call) and `wait`.
