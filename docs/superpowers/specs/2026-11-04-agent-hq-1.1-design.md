## 1. Orchestrate (M5c)

**What it does.** You give a goal. A *planner* run writes a plan of steps. You review and edit the plan, then start it. Agent HQ runs the steps as normal runs, respecting each step's dependencies and choosing a tool and account for each. The team works on one goal branch, and you merge the result once, at the end.

**Flow:**
1. **Goal sheet:**
   - your goal text;
   - the project (from the allowlist);
   - the **highest level** steps may use (read-only, ask or edit, default edit; **full auto is never allowed for planned steps**);
   - a step limit (default 6, at most 10);
   - a total time limit (default 90 min, at most 4 h);
   - the planner tool (default Claude Code at read-only).
2. **Planner run.** A normal read-only run in the project, with a fixed instruction wrapped around your goal. It must answer with one fenced JSON block:
   ```json
   {"steps": [{"id": "s1", "title": "…", "prompt": "…", "kind": "code|review|research", "depends_on": [], "tool": "codex|claude|opencode|agy|null"}]}
   ```
3. **Plan review.**
   - The plan is parsed **as untrusted data** and validated:
     - ids are unique, and `depends_on` contains no cycles;
     - there are at most the step limit;
     - each prompt is at most 20,000 characters;
     - tools are only the tested ones.
   - A step's level is `min(goal max level, its kind's default)`, where `review` and `research` default to read-only and `code` defaults to edit.
   - In the UI you can edit any title, prompt, tool or dependency, and delete steps. Nothing runs until you press **Start plan**, which takes a confirm nonce.
4. **Scheduling:**
   - A step starts when its dependencies are done. Steps without a dependency between them run in parallel, up to `max_concurrent`.
   - Routing per step: your pick if set, otherwise Auto-route (provider-usage `recommend`, task kind from `kind`, through the guard and pool).
5. **Branches:**
   - The goal has a branch `hq/goal-<id>`, created from the project HEAD.
   - Each step's worktree starts from the goal branch's current head.
   - When a step finishes, its snapshot commit is merged into the goal branch automatically (fast-forward or merge commit). This happens **in Agent HQ's own worktree, never in your checkout**.
   - A merge conflict pauses the goal ("needs you"), and you resolve it in a terminal or discard that step.
6. **Finishing.** When all steps are done, the Goal page shows the goal branch's diff against its base, with **Merge into project** (merging exactly the viewed commit, as for runs) and **Discard goal**.

**Stops:**
- a step failure pauses the goal, with Retry step, Skip step or Stop goal;
- reaching the total time limit stops everything;
- **(default)** no automatic retries.

**Data:**
- a `goals` table: id, project, text preview, max_level, status, branch, base_commit, plan JSON, step limit, time limit, created_at and ended_at;
- runs gain `goal_id` and `step_id`.

**UI:**
- a **Goals** page: a list of goals, and the goal detail with its plan graph, step runs (linked to the run detail) and the final diff;
- in the office, a goal's agents **gather at a team table** (see §3).

**Security:**
- planner output never grants anything: levels are capped, tools come from an allowlist, and every step goes through the run engine's guards;
- you start the plan, with a nonce bound to the exact plan JSON;
- steps never run at Full auto.

## 2. Remote runs

**What it does.** You start runs on a host from `hosts.json`, like local runs, for **Linux and macOS hosts (default)**. Windows hosts and containers can be watched but not run. Remote runs show up live, link to their remotely watched sessions, and support stop, diff, merge and discard.

**Config.** A host gains `"run": true` and `"projects": [{"name", "path"}]`, which is the remote allowlist. Tools are detected on the host and offered only when that tool is tested locally too.

**How:**
- One fixed helper script, `hq/remote/runner_helper.py`, is sent over ssh (`python3 -`), like the scanner.
- Its request is embedded as a string literal: action (`start`, `stop`, `diff`, `merge`, `discard`, `tools`), run id, project name, and a **launch spec built locally by the same launchers** (argv list, env names, stdin text).
- **The helper:**
  - resolves the project from the host's allowlist on the remote side;
  - creates the worktree with explicit `--git-dir`/`--work-tree` and hardened git options, as locally;
  - starts the tool with `os.execvp`, never a shell, under `setsid`, writing a pid file;
  - streams stdout lines back over the same ssh connection.
- **stop** is a second ssh call that sends the process group SIGTERM, then SIGKILL after 3 s.
- **diff, merge and discard** run the helper's git functions with the same rules as local runs.
- **Environment:** the helper filters the remote environment with the same allowlist rules as local runs.
- **ssh:** the same fixed options as watching, plus `ServerAliveInterval=15`. A dropped connection marks the run `interrupted`; the remote process group is killed by the helper's watchdog when its stdin closes.

**Security:**
- every value sent is validated locally (run id, project name, argv built by local launchers);
- the helper re-validates on the remote side;
- nothing from the host is trusted: output lines are parsed with the same stream rules, and session ids are validated.

**Test.** A real Codex run on `debian-test` (read-only, then edit, then diff, merge and discard), with the remote session linked through remote watching.

## 3. Office extras (M6)

- **Thought bubbles:** a figure shows a small bubble with its current step: the last tool, such as "Edit app.py", or a short preview. It appears on hover, on selection and on new events, and fades after 6 s.
- **Emotes** (2 s each):
  - ✓ when a turn ends;
  - a red puff on error;
  - "!" on a new approval;
  - "💤" when idle more than 10 min.
- **Team table:** agents of a running goal walk to a shared table in a team zone and sit around it while their steps run.
- **Follow camera:** click a figure, then "Follow" keeps it centred, through walks and floor changes. Esc stops following.
- **Timeline replay:**
  - a scrubber for the last 24 h (default), at 1×, 10× or 60× speed;
  - figures replay their states and walks from stored events;
  - "Live" returns to now.
  - It's read-only and uses the existing events API, plus a new `GET /api/timeline?from=&to=`. That returns at most 20,000 events and only the columns the office needs.
- **Layout editor:**
  - drag zones and desks in the top-down and isometric views, and rename zones;
  - **(default)** saved in your browser (`localStorage`) per skin, with Reset layout;
  - nothing is written on the server.
- **Motion rules** (from the spec §6.1 design rules): reduced motion replaces walks with fades and turns emotes into static badges.

## 4. More Ask me and live follow-ups

- **opencode via ACP:**
  - a new launcher mode, `acp`: `opencode acp --cwd <workdir>` with `OPENCODE_CONFIG_CONTENT` setting the model and `permission` (`ask` for the Ask me level; `allow` for edit);
  - the runner speaks JSON-RPC: `initialize` → `session/new` (or `session/load` to resume) → `session/prompt` for each turn;
  - `session/request_permission` becomes an Inbox approval. The answer is the allow or reject `optionId`;
  - `session/update` notifications become the output and conversation;
  - the session id comes from `session/new`, validated as now.

  The opencode launcher offers **Ask me** and goes live for follow-ups. Any other JSON-RPC request from opencode (`fs/*`, `terminal/*`) gets a JSON-RPC error, because Agent HQ doesn't offer those capabilities.
- **Antigravity live follow-ups:** a live run with `--input-format stream-json`, using the `{"event":"user",…}` shape. Ask me stays off (see §0).
